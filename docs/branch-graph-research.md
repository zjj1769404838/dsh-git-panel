# Git 分支可视化调研与差异分析

> 调研限制说明：本机 `web_search` 不可用（`DeepSeek search has no API key for "DEEPSEEK_API_KEY"`），
> 因此外部案例部分依据已确立的成熟实现（gitk / `git log --graph` / GitHub Network / VS Code Git Graph /
> GitKraken / Sourcetree）的通行设计，并用**本机实测证据**校准：真实多分支仓库的 `git log --graph`
> ASCII 车道输出、以及宿主自身时间线组件（`@deepseek-ai/dsh-client-ui-trajectory`，bundle 内 `lane` 出现 17 次）
> 的泳道式布局。

## 一、参考案例与可复用方案

### 1. 车道（lane）式拓扑 —— 业界共同解
所有主流实现都不画「自由曲线图」，而是把提交按拓扑序排成行，为每条活跃分支分配一条**固定车道**，
行内只有三种图元：

| 图元 | 语义 | 绘制 |
|---|---|---|
| 节点（dot） | 一个提交 | 车道 x 上的实心圆，当前 HEAD 加大 + 外环 |
| 竖线（pass-through） | 某车道正等待下方的提交 | 同车道 `r → r+1` 的直线 |
| 转折线（curve） | 分叉或汇合 | `(laneA, r)` 到 `(laneB, r+1)` 的 S 形三次贝塞尔 |

关键点：**跨行的长连线不存在**。一条分支跨 N 行，靠 N 个竖线段连续拼出，
所以永远不会穿过中间的节点 —— 这是「避免连线重叠/错位」的根本手段，比事后避让可靠。

### 2. 分叉与汇合的视觉表现
- **分叉**：父提交在本行车道 `L`；提交本身只有一个父时线直落 `L`。当第二个父被分配新车道 `M` 时，
  从 `(L, r)` 曲线到 `(M, r+1)` —— 视觉上「一条线从主干上岔出去」。
- **汇合**：被合并的提交在其车道里已有竖线在等待；合并提交本行再画一条从 `L` 到该车道的曲线，
  两线在下一行同一节点相交 —— 视觉上「两条线收拢到一个点」。
- 车道复用的判据：**新父提交若已有车道在等待，就复用那条车道**（不新建），否则取最小空闲车道。
  这样 `feature` 合回 `main` 后其车道立即被回收，图宽不会无限增长。

### 3. 节点、分支名、方向标识的布局
- 节点：左列车道区，行高 24–28px，车道间距 12–14px（gitk 为 13px 级别）。
- 分支名：**不放在每个节点旁**（否则密集时糊成一片），而是只在**带 ref 的节点**右侧显示为 chip
  （`main` / `origin/main` / `v1.0.0` / `HEAD`），样式区分 local / remote / tag。
- 方向标识：Git 的 DAG 本身无方向箭头，业界统一约定「**新→旧自上而下**」，靠行序表达方向，
  不用箭头（箭头在密集图上会互相遮挡）。额外用 `↑N ↓N`（ahead/behind）表达与上游的相对位置。

### 4. 分支颜色与线条区分
- 颜色按**车道索引**取色（不是按分支名哈希）：车道是稳定分配的，颜色因此稳定；
  分支合并后车道回收，新分支复用色位，视觉上不会越来越花。
- 8 色循环（蓝/绿/琥珀/紫/天蓝/粉/橙/石板灰），浅深主题各一套，保证同一条线上深浅模式都能读。
- 线宽统一 1.5px，节点半径 4.5px；**不使用虚线**区分（虚线在密集图上产生摩尔纹），
  改用颜色 + 节点大小（HEAD 更大）区分主次。

### 5. 横向 vs 纵向、间距、缩放自适应
- 主流全用**纵向**（新在上），因为提交消息是横排文本，纵向排布可读性最好；横向只适合极窄的
  「分支条」概览。
- 行高固定、车道宽固定 → 缩放只需改这两个常量，不用重排；窗口变窄时**横向滚动**比压缩车道宽更好
  （压缩后 8 条以上车道会糊）。
- 默认只渲染最近 N 条（本实现 30 条，可调 10–100），超出提示「已截断」——这是 gitk/GitHub 的共同策略。

### 6. 交互反馈（业界标配）
- **悬浮**：节点放大 + tooltip（完整 hash / 作者 / 日期 / 标题）。
- **选中**：点击行高亮该行，底部详情条显示完整提交信息。
- **分支高亮**：当前分支节点加外环；hover 分支 chip 时高亮该分支整条车道。
- **分支切换**：在 GitKraken/Sourcetree 是双击 chip 触发 checkout。**本实现不新增此能力**——
  它会扩大写操作面，而现有 `git_write` 工具已覆盖 checkout 且强制走「说明动作 + 确认」闸门。
  这里只做只读可视化，符合「保持现有功能与业务逻辑不变」。

## 二、当前实现 vs Git 分支式可视化：差异清单

| 维度 | 当前实现（`dgp-v7` 菜单） | Git 分支式可视化 | 差异性质 |
|---|---|---|---|
| 信息形态 | 纯文本摘要：`root · branch` + 4 个操作项 | 提交 DAG 图（节点 + 车道 + 连线） | **本质缺失**：没有任何拓扑信息 |
| 提交历史 | 完全没有 | 逐行提交（hash / 标题 / 作者 / 日期） | 缺失 |
| 分叉汇合 | 不可见 | 车道曲线表达 | 缺失 |
| 分支关系 | 只有当前分支名一个字符串 | 多分支并行车道 + ref chip | 缺失 |
| 颜色语义 | 无 | 按车道取色，稳定可区分 | 缺失 |
| 交互 | 点击菜单项执行动作 | 悬浮提示 / 选中行 / 分支高亮 | 部分缺失 |
| 空间 | 236–320px 宽、竖向菜单 | 380–460px 宽、可滚动图区 | 需要放大浮层 |
| 数据来源 | `GET /repo/status`（单仓库状态） | 需要提交 DAG（hash/parents/refs） | **数据结构不足，需最小扩展** |

结论：问题不在「配色/间距」这类局部样式，而在**当前浮层根本没有表达分支结构的数据与图元**。
因此本轮改造 = 新增一个只读 DAG 接口 + 一个车道布局算法 + 一个 SVG 渲染层，
其余（检测四态、初始化入口、复制路径、打开设置、portal 定位、z-index、主题 token）全部保留。

## 三、映射到本项目的实现方案

1. **数据（最小扩展）**：`GET /repo/graph?cwd=&limit=` → 复用既有 `runGit`，
   `git log --all --date-order -n<limit> --pretty=format:%H%x1f%h%x1f%P%x1f%an%x1f%ad%x1f%D%x1f%s`。
   字段分隔用 `\x1f`（unit separator），避免提交标题里的空格/竖线干扰解析。
2. **布局**：`layoutGraph(commits)` 纯函数（node 侧，便于回归测试），输出每行
   `{lane, segments:[{from,to}], through:[lane...]}` 与 `laneCount`；规则见上文 1–2。
3. **渲染**：client 侧 SVG，`laneX = LANE_PAD + lane*LANE_W`（`LANE_PAD = 9`、`LANE_W = 13`）、
   `rowY = row*ROW_H + ROW_H/2`（`ROW_H = 34`）；同车道竖直直落，跨车道三次贝塞尔
   （`C x1 y1+half, x2 y2-half, x2 y2`，`half = ROW_H/2`）。行高取 34px 是因为
   每行是「12px/16px 标题 + 10px/13px 副行」的两行文本，26px 会压行。
4. **交互**：行 hover 高亮 + `<title>` tooltip；点击选中并在详情条显示完整信息；
   当前 HEAD 节点加外环；ref chip 分 local/remote/tag 三色。
5. **降级**：非仓库 / 检测失败 / 空仓库（无提交）时**不渲染图**，仍走原有菜单项，
   保持「未初始化 → 初始化入口」的既有业务逻辑不变。

## 五、落地后的偏差记录（实现阶段校准）

调研阶段的几个估计值在实现时被实测修正，记录在此以免后续误用：

| 项 | 调研初稿 | 落地值 | 原因 |
| --- | --- | --- | --- |
| 行高 | 26px | **34px** | 每行是两行文本（标题 16px + 副行 13px），26px 会把副行压出格子 |
| 图区与文本的关系 | SVG 绝对定位 + 文本左留白 | **同一 flex 行的两个子元素** | 绝对定位在 `overflow:auto` 的滚动容器里会与文本脱开，滚动时错位 |
| 同车道连线 | 只画 `through` | **`segments` 里 `from === to` 的也要画** | 只画 `through` 会让主干相邻节点之间没有线，图变成一串孤立的点 |
| 颜色 | 按分支名哈希 | **按车道索引**（`--dgp-lane-0..7`） | 车道稳定 → 颜色稳定；按名哈希在同一分支换车道后会跳色 |
